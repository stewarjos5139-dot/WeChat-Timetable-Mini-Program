# 部署到微信云托管

把 `server/` 部署成云托管容器，小程序通过 `wx.cloud.callContainer` 调用。

**这条路不需要自己的服务器，不需要域名，也不需要 ICP 备案。**

> ⚠️ 标注「需核实」的是我无法确认的外部事实（控制台选项名称、定价、`callContainer` 参数）。
> 界面可能改版，以控制台和[官方文档](https://developers.weixin.qq.com/miniprogram/dev/wxcloudrun/src/)为准。

---

## 一、开通与创建（控制台操作）

1. **进云托管**：微信开发者工具 → 上方「云托管」面板；或腾讯云 CloudBase 控制台
2. **创建环境**，记下**环境 ID**（形如 `ilove-caida-1a2b3c`）
3. **新建服务**，记下**服务名**（形如 `schedule`）
   - 服务名后面要填进小程序代码，起个短的好记
4. **配置容器端口**：填 `80`
   - 必须和 `Dockerfile` 里的 `EXPOSE 80` / `ENV PORT=80` 一致，否则连不上
5. **配置部署方式**：选「本地代码上传」或 Git 仓库
   - 代码目录指定为 `server/`
   - `Dockerfile` 已在 `server/` 目录下，构建时会自动用它

---

## 二、填进小程序

### 路 A：云托管内部调用（推荐，真机和发布版唯一可行的一条）

拿到**环境 ID**和服务名后，填 `utils/config.js`：

```js
module.exports = {
  CLOUD_ENV: '你的环境ID',
  SERVICE_NAME: '你的服务名'
}
```

**环境 ID 在哪儿找**：微信开发者工具的「云托管」面板顶部通常有环境切换器，旁边显示环境 ID；
或腾讯云 CloudBase 控制台 → 云托管 → 环境设置。

> ⚠️ 注意区分三个东西：**服务名**（你填的 `xingmeng`）、**环境 ID**（`callContainer` 要的是这个）、
> **公网默认域名**（形如 `xxx.sh.run.tcloudbase.com`，那是给外部 HTTP 访问用的，不是环境 ID）。

### 路 B：打公网默认域名（只够模拟器联调用）

云托管会给每个服务分配一个公网默认域名，形如：

```
xingmeng-322641-10-1499548475.sh.run.tcloudbase.com
```

填进 `BASE_URL` 可以**立刻在开发者工具里验证部署是否成功**，省得卡在找环境 ID 上：

```js
module.exports = {
  BASE_URL: 'https://xingmeng-322641-10-1499548475.sh.run.tcloudbase.com'
}
```

**但这条路真机走不通** —— 它用的是 `wx.request`，域名必须在微信后台的 request 合法域名
列表里，而这个域名不是你的，配不了。所以：

- 模拟器验收 → 路 B 够用，还更快
- 真机 / 发布 → 必须用路 A

两组都填时，`utils/api.js` 优先走路 A。

填完之后，登录页顶部那条「中间层尚未配置」的黄色提示会自动消失。

## 三、验证

按顺序做，每步都能独立定位问题：

### 1. 本地回归（改代码后必做）

```bash
cd server && node selftest.js      # 应 27 项全过
```

### 2. 本地跑通服务

```bash
cd server && node index.js
```

另开一个终端：

```bash
# 新增的健康检查，应回 {"ok":true,...}
curl http://127.0.0.1:3000/health

# 后端本身能不能登进教务系统
node try.js <学号> <密码> 2026 3
```

第 2 条能拿到课表，说明 `server/zfsoft.js` 没问题，可以往云端部署了。

### 3. 云端容器自测

部署完成后，先在**云托管控制台的日志/测试面板**确认容器自己跑得通：

- 健康检查应该在自动通过（`GET /` 返回 200）
- 用同样参数调一次 `/api/schedule`
- 日志里应出现 `[schedule] 成功 学号***XXXX → NN 条`

**这一步不过就别往小程序里测** —— 分不清是容器的问题还是小程序调用的问题。

### 4. 小程序端到端（开发者工具模拟器）

我的 → 导入课表 → 填表 →「已导入 N 门课」→ 课表页渲染出真实课表。

核对：周次数、今天那列高亮、**晚课（11-13 节）是否显示**、点方块的详情。

### 5. 真机验证

真机调试走一遍导入。**这是云托管相对自建的核心收益，必须验** —— 确认无需备案域名即可连通。

## 四、计费

⚠️ **需核实** —— 云托管按容器运行时长计费，具体价格和免费额度请查控制台定价页。

**建议：最小实例数设为 0。**

理由是这个中间层**每学期只在「导入课表」时被调用一次**，之后全靠小程序本地存储。常驻实例（最小 1）会一直计费，而冷启动多等的那几秒，在「一学期导入一次」的场景下完全无所谓。

## 五、常见问题

| 现象 | 原因 |
|---|---|
| 部署成功但调用超时 | 容器端口配错，或 `HOST` 没设成 `0.0.0.0`（`Dockerfile` 里已设） |
| 容器反复重启 | 健康检查失败。确认 `GET /` 返回 200（`server/index.js` 已加） |
| 小程序报「云托管调用失败」 | `utils/config.js` 里的环境 ID 或服务名填错 |
| 导入时提示登录失败 | 教务系统那边的问题，不是部署问题。用 `try.js` 本地验证一次 |
| 导入耗时很长（十几秒） | 正常 —— 后端要串行发 11 次请求到教务系统。若超过网关超时上限则需精简请求链 |

## 六、其他

**自建 HTTPS 服务**是另一条路（需要服务器 + 备案域名 + nginx），详细步骤见同目录的 [`README.md`](README.md)。那条路适合日后有备案域名、想完全掌控的情况，服务端代码和这条路**完全共用**。

切换回自建只需要改 `utils/api.js` 里的 `request()` 一个函数 —— 文件末尾有说明。
